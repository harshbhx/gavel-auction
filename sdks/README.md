# GAVEL SDKs

Client libraries (TypeScript, Python, C#) for the GAVEL host API, generated by APIMatic from the OpenAPI 3.1 document
[`openapi/gavel.yaml`](../openapi/gavel.yaml). Package name `gavel-sdk`, version 0.0.5 (beta).
Sandbox only: the default server is the PayPal sandbox host, no real money moves.

| Language   | Folder                     | Package         | Import                              |
| ---------- | -------------------------- | --------------- | ----------------------------------- |
| TypeScript | [typescript](typescript/)  | `gavel-sdk`     | `import { ... } from "gavel-sdk"`   |
| Python     | [python](python/)          | `gavel-sdk`     | `import gavel_host_api`             |
| C#         | [csharp](csharp/)          | `GavelSdk`      | `using GavelHostApi;`               |

Each folder has its own README, an API reference and an SDK map written by the generator.

## Install

The packages are published as GitHub Releases, not on npm, PyPI or NuGet. Download the asset from the
[releases page](https://github.com/harshbhx/gavel-auction/releases) (tags named `sdk-v<version>`).

```bash
# TypeScript
npm install ./gavel-sdk-0.0.5.tgz

# Python
pip install ./gavel_sdk-0.0.5-py3-none-any.whl

# C# (the folder holding GavelSdk.0.0.5.nupkg is used as a local package source)
dotnet add package GavelSdk --version 0.0.5 --source .
```

## Release process

`.github/workflows/sdk-release.yml` builds both packages on every pull request that touches
`sdks/`, and creates the GitHub Release when a tag `sdk-v<version>` is pushed. It needs no
secret beyond the built-in `GITHUB_TOKEN`.

## Regenerating

The folders are generator output with the package name and version patched to `gavel-sdk` and
0.0.5. Regenerate only when the API changes and the maintainer asks for it, then repeat the
patch.
