# Accessibility (R-WEB-109 to R-WEB-118, R-QA-037)

This file records how accessibility is checked in GAVEL, what runs automatically, and what still
needs a human. It does not claim any manual result that nobody has recorded.

## Automated checks

All of these run in CI. The Playwright specs run in the `web-visual` job of
`.github/workflows/browser-specs.yml` through `npm run test:a11y -w @gavel/web`, with or without
committed screenshot baselines.

| Check                         | Where                                         | What it asserts                                                                  |
| ----------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------- |
| axe-core on states (unit)     | `packages/web/test/component/a11y.test.tsx`   | No serious or critical violation on component and screen state fixtures.         |
| axe-core in a browser         | `packages/web/test/visual/a11y.spec.ts`       | Zero serious or critical violations on every route, light and projector themes.  |
| Keyboard walks                | `packages/web/test/visual/keyboard.spec.ts`   | Tab reaches controls, focus ring at least 2 px and 3:1, dialog trap and restore. |
| Reduced motion, forced colors | `packages/web/test/visual/motion.spec.ts`     | Animation duration 0s under reduce; chips and stamp keep a border when forced.   |
| Responsive                    | `packages/web/test/visual/responsive.spec.ts` | Reflow at 320 px and 200 percent zoom, screen view sizes.                        |
| Register walk by keyboard     | `packages/web/test/visual/keyboard.spec.ts`   | Name, paddle, ceiling and approve reachable with Tab, Enter and Space only.      |
| Ladder in forced colors       | `packages/web/test/visual/motion.spec.ts`     | Rungs keep icon and label; the current rung has a 2 px Highlight border.         |
| axe on the e2e stack          | `packages/e2e/specs/a11y-axe.spec.ts`         | No serious or critical violation on routes, register steps and the open dialog.  |
| Keyboard and live region      | `packages/e2e/specs/a11y-keyboard.spec.ts`    | Register form in 8 Tab presses or fewer; live region update within 200 ms.       |
| Public screen legibility      | `packages/e2e/specs/public-screen.spec.ts`    | Price text 96 px or more, base text 28 px or more, 7:1 in the projector theme.   |

Rules the specs enforce: no horizontal scroll except inside the audit table, the price text on the
public screen is large, the live region announces results, and route changes move focus to the
main heading.

## Known gaps in automation

- Blocked (view not reachable with a scripted room on main): the bid screen (open, paused, closed
  and stopped), the console, the public screen, the receipt (held and settled) and the audit view
  with a room behind them. The scenario transport is mounted only for the replay screen, which
  renders a title and a price. Every other room route mounts the WebSocket transport, and with no
  stored token `/r/demo/console`, the audit and the screen render the placeholder. A live room
  needs the real server: the e2e fixture would have to create it with the admin key and hand the
  browser an auctioneer link and bidder session, which `packages/e2e/src/fixtures/base.ts` does not
  expose today. Until then no spec drives these views, and none is faked.
- Blocked for the same reason: the bid-button focus check after a bid result (R-WEB-111), and the
  console hammer path (focus, Enter, confirm dialog with trap and Escape restore, R-WEB-113). The
  hold-by-Enter behaviour is covered only by `packages/web/test/component/ConsoleControls.test.tsx`.
  The 7:1 and 96 px checks on the public screen run on a probe, not on real room state.
- Not performed in a browser: the keyboard walk past the register form, because the approve step
  needs a payment return.
- Focus ring on radio buttons is not measured: the keyboard spec measures text fields and buttons.
- Added by this change, and limited as follows. The register walk runs on a stored session that
  stands in for the invite step. The settlement ladder is checked in forced colors from a
  specimen on the gallery page at /gallery?ladder (a fixed settlement view), and its screenshot is a report
  attachment, not a compared baseline. The public screen legibility check reads computed styles
  from a probe built from the screen's own classes. The live region timing check calls the app's
  own announcer from the page.
- The e2e specs `packages/e2e/specs/a11y-axe.spec.ts`, `a11y-keyboard.spec.ts` and
  `public-screen.spec.ts` run on the e2e stack in the `e2e` jobs of
  `.github/workflows/browser-specs.yml`; their axe results are attached to the Playwright report
  as JSON.
