- **SEC-19** OPEN (new, not yet reviewed by someone other than its author). Threat: a create route that needs no operator key (`POST /api/judge/rooms`) lets anyone on the internet open real sandbox rooms, so it could be used to exhaust the host, to mint a token that reaches operator routes, to leave rooms running, or to point real PayPal at an unattended endpoint. Mitigations: the route answers 404 unless `JUDGE_ROOMS=true`; boot validation refuses the flag with a non-sandbox `PAYPAL_ENV` or `PAYPAL_BASE_URL` and, on a production-like host, without `PAYMENTS=sandbox`; `DEMO_MODE` stays refused in production; per-address and host-wide hourly create limits (the address is stored only as a short hash); a cap on live rooms counted before the first await so a burst cannot overshoot it; a fixed safe lot (small reserve, short window, ceilings under the payments cap); the response carries room-scoped auctioneer and screen tokens only, which every admin route rejects (they need `x-admin-key`); a sweeper ends each room at its lifetime, voids unsettled holds through the normal abort path and revokes the creator token; every audit line carries `judgeRoom: true`; the operator can switch creation off at runtime with `POST /api/judge/pause` (admin key) or boot paused with `JUDGE_ROOMS_PAUSED=true`. Residual: judges behind one shared address share the per-address limit (`JUDGE_ROOMS_PER_IP_HOUR`); an attacker with many addresses can fill the room cap and block judges until rooms expire; the real sandbox path (hold, hammer, void) is covered by the fake PayPal in CI and by a sandbox spec that is skipped without secrets.
- **SEC-20** OPEN (new, not yet reviewed by someone other than its author). Threat: a receipt link is passed around, so whatever its token opens is opened for whoever holds it. Mitigations: the token is its own kind (`receipt`) with a four hour lifetime equal to the bidder session; it names one bidder in `sub` and carries no `bidderId`, so every route that wants a session, screen or auctioneer token refuses it and the socket join refuses it; it opens exactly one read-only route, `GET /api/auctions/:id/receipt`, which refuses every other kind; it is minted only by `POST /api/auctions/:id/receipt-link` from that bidder's own session token; the response is the bidder snapshot cut down to the lot title, the hammer outcome, the holder's own roster row (display name and paddle), the winner's paddle without a name and the holder's own hold (no other bidder, no audit rows, no join code, no ceiling object); the token rides in the URL fragment, which the browser never sends to a server or a log and the app removes from the address bar after reading it. Tests: `http-receipt.test.ts` (scoping, expiry, tampering, wrong audience, wrong kind, redaction), `token.test.ts`. Residual: a copied link works until it expires and cannot be revoked one by one (the same as a session token); the QR code and the printed page carry the link.

- **SEC-21** PARTIAL (new, tested, not reviewed by someone other than its author). Threat: a second key that skips the public room limits could be guessed, leaked or turned into operator access. Mitigations: `JUDGE_KEY` is a different secret from `ADMIN_KEY` (boot refuses them equal) and opens only keyed judge rooms, never an admin route; the header is compared in constant time; a wrong key answers 401 and counts as a strike on the same lockout as a wrong room code (five strikes, 15 minutes), and a locked-out address is refused even with the right key; keyed rooms have their own cap (`JUDGE_KEY_ROOMS_MAX`, 3 by default) and 20 creates per hour; every keyed action is audited with the source as a short hash and never the key; the web app keeps the key in `sessionStorage` for the tab and never in a URL. Tests: `http-judge-key.test.ts`, `config-judge-key.test.ts`, `boot-judge-key.test.ts`, `client-key-parity.test.ts`. Residual: a leaked key lets its holder open up to the keyed cap until the key is rotated on Render; the lockout is per address hash, so many addresses can still guess slowly; no live check with a wrong key was recorded.
- **SEC-22** PARTIAL (new, tested, not reviewed by someone other than its author). Threat: a link meant for reading is used to act. Mitigations: the `reviewer` token is its own kind (12 hours, `auth/token.ts`), has a screen's read view, and is refused by every bid, control, join and mint route; `GET /api/judge/rooms/:id/ledger` accepts only a `reviewer` or `auctioneer` token for that room, exists only for judge rooms, and checks the hash chain before it answers (a broken chain answers 409, not a bundle that looks fine); the response is `no-store`. Tests: `http-judge-rooms.test.ts`, `token.test.ts`. Residual: a copied reviewer link works for its 12 hours and cannot be revoked one by one; the bundle contains the room's public audit trail, which is read-only but not secret.
- **SEC-23** PARTIAL (new, tested, not reviewed by someone other than its author). Threat: a hold that skips PayPal could be used outside a judge room or be mistaken for a real one. Mitigations: simulated holds exist only in judge rooms and only while `JUDGE_SIM_HOLDS` is not `false`; the authorization id carries the `sim-auth-` prefix and `withSimulatedHolds` answers only those ids, so a normal hold never reaches that code and a simulated id never reaches PayPal; boot refuses judge rooms on a non-sandbox PayPal setting; no money is held or moved, and the join screen offers the simulated hold beside the PayPal sandbox option. Tests: `http-judge-sim-hold.test.ts`, `sim-holds.test.ts`, `boot-judge-sim-hammer.test.ts`. Live: `GET /api/judge/capabilities` reports `simHolds: true` (2026-11-09). Residual: a simulated settlement is remembered only by the running process (a restart reads the hold as still held and the settlement retries); no live simulated bid was placed for this review.
- **SEC-24** OPEN. The docs site sets its headers through `docsite/public/_headers` and the `docsite` workflow checks that the file reaches the export. Not verified: that the live docs host and the custom domains (`gavel.dualmindlab.tech`, `docs.gavel.dualmindlab.tech`) send those headers, and whether Cloudflare adds scripts on the custom domain that the CSP must allow. A reviewer re-runs `curl -sI` against each host and records the result here.
