## Question

After authorizing 500.00 and <Term id="capture">capturing</Term> 350.00 with `final_capture=true`, is the 150.00 remainder released, or still active? GAVEL charges only the winning price, so this decides whether the <Term id="saga">saga</Term> must <Term id="void">void</Term> the remainder itself.

## Method

- Workflow: [`gate-g1`](https://github.com/harshbhx/gavel-auction/blob/main/.github/workflows/gate-g1.yml), by hand, `main` only. A headless browser signs in as the <Term id="sandbox">sandbox</Term> buyer to approve the order.
- Script: `gates/g1.ts` in `packages/payments` (package script `gate:g1`).
- Steps: create order (AUTHORIZE 500.00), buyer approval, authorize, capture 350.00 with `final_capture`, read the <Term id="authorization">authorization</Term> and the order, then try an explicit void of the remainder.
- Two buyers, two runs: a wallet buyer (4 Nov) and a second buyer funded by a card (5 Nov, run `G1-20261105T123116Z`). Both orders use `payment_source.paypal`, so both are PayPal-account orders. The second buyer is a personal sandbox account, not a guest card checkout.

## Limits

<NotVerified title="The remainder release is inferred">

No run read a buyer balance or available funds. The authorization keeps amount 500.00 after the capture, so the evidence cannot tell a released remainder from an open one. Release is inferred from the CAPTURED status, the 422 on the later void and PayPal's documentation.

</NotVerified>

- PayPal-account buyers only. No `final_capture` and no 350.00 hammer capture was run on a guest card order. A later early G3 probe accepted a partial capture of 1.00 on the guest card authorization; it does not change the G1 verdict.
- It does not measure latency or <Term id="webhook">webhooks</Term>.
