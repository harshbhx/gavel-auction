## Question

Does the PayPal <Term id="sandbox">sandbox</Term> app authenticate, and can it create an order with intent `AUTHORIZE`? Every later real-sandbox <Term id="gate">gate</Term> depends on this, so it runs first.

## Method

- Workflow: [`gate-g0`](https://github.com/harshbhx/gavel-auction/blob/main/.github/workflows/gate-g0.yml), started by hand (`workflow_dispatch`). The job declares the `sandbox-nightly` environment and runs only from `main`.
- Script: `gates/g0.ts` in `packages/payments` (package script `gate:g0`). It makes a client-credentials token request, then creates one order with intent AUTHORIZE, and checks that the approve link is present.
- Secrets used, by name: `PAYPAL_CLIENT_ID` and `PAYPAL_CLIENT_SECRET`. Values are never recorded.
- Sandbox accounts behind the gates: one business account that owns the app and five personal US buyer accounts, all in USD.

| Check | Expected | Observed |
| --- | --- | --- |
| G0.1 token | HTTP 200, payments scope | HTTP 200, payments scope |
| G0.2 create AUTHORIZE order | HTTP 201 CREATED | HTTP 201 CREATED, intent as sent |
| G0.3 approve link | present | present |

## Limits

- It proves connectivity, token scopes and order creation only.
- No buyer approval and no <Term id="capture">capture</Term> were part of G0.
- It says nothing about card or guest buyers ([G2](/docs/proof/gate-g2)), partial capture ([G1](/docs/proof/gate-g1)) or webhooks ([G4](/docs/proof/gate-g4)).

## If it fails

There is no fallback for payments. Hold G1 to G4 and demo on the <Term id="fake-paypal">fake PayPal</Term>, labelled as fake. See the [operator runbook](/docs/run/operator-runbook) and [gate runbook](/docs/run/gate-runbook).
