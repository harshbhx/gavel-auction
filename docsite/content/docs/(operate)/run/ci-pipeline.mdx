<Callout type="warn" title="The sandbox environment protects nothing yet">
The job names the GitHub environment `sandbox-nightly`, but it has no reviewer, no branch rule and no secrets of its own. The secrets are repository-level, so a workflow file on any pushed branch can read them. That is why only throwaway sandbox values are allowed in them.
</Callout>

## When a check goes red

<Steps>
<Step>

Open the failed run and read the failing job: `gh run view <run-id> --log-failed`.

</Step>
<Step>

If it is `required`, the failing job is named in its log; fix that job, not the roll-up.

</Step>
<Step>

If a scheduled evidence workflow ended red because secrets are missing, that is by design: a night that tested nothing must not look like a pass. Add the secrets named in its notice.

</Step>
<Step>

Download artifacts with `gh run download <run-id> -n <artifact-name>`: `sandbox-report`, `g3-probe-state`, `g3-entry`, `g3-early-evidence`, `sim-multiday-report`, `ui-screens`, `judge-smoke-traces`, `docsite`, `docsite-shots`.

</Step>
</Steps>
