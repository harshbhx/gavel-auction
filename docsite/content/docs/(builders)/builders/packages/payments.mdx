`@gavel/payments` (`packages/payments`) is everything that talks to PayPal, and the fake PayPal that stands in for it in tests. Its one runtime dependency is `zod`; it uses `node:crypto` and `node:fs` itself. PayPal is the sandbox only: `loadConfig` throws `payments_not_sandbox` unless `PAYPAL_ENV` is exactly `sandbox`, and `guard.ts` refuses any host other than the sandbox API and approve hosts (loopback only in fake mode).

## Responsibilities

- **A gateway to PayPal.** `PaymentsGateway` (`ports.ts`) has `createOrder`, `getOrder`, `authorizeOrder`, `getHoldTruth`, `capture`, `voidAuthorization` and `reauthorize`. Its comment states the rule the saga builds on: a `PayPalError` with outcome `definite` means the request provably did not take effect; outcome `unknown` means it may have, and the caller must read the truth first.
- **Transport with retry.** `transport.ts` retries network errors and the statuses 429, 500, 502, 503 and 504; every attempt of one logical request carries the same request id. The per-attempt timeout defaults to 10 seconds.
- **Holds.** `HoldService` (`holds/service.ts`) creates a bidder's hold order, completes the approval and returns the same order for a double click or a second tab, because calls for one auction and bidder run one after the other.
- **The settlement saga.** A pure state machine (`saga/machine.ts`) driven by runners for create, capture, fallback, unknown outcome, void, remainder, reauthorization and the kill switch. Each transition is saved to a journal before the effect runs.
- **Idempotency.** `buildRequestId` (`requestId.ts`) derives `gv1-` plus a hash of auction id, operation (`order`, `authorize`, `capture`, `void`, `reauth`), hold id, amount in cents and a generation. The generation changes only when parameters change, never on retry or resume.
- **Webhooks.** `webhooks/verify.ts` checks the signature with PayPal's own verification call on the original bytes; `dedupe.ts` keys events by PayPal's event id; `merge.ts` and `orphans.ts` make the final hold status independent of delivery order.
- **Reconciliation.** `reconcile/reconcile.ts` compares journal and hold records with what PayPal reports and returns findings (`AMOUNT_MISMATCH`, `EXTRA_CAPTURE`, `LIVE_HOLD_AFTER_SETTLED`, `MISSING_CAPTURE`, `REFUNDED_CAPTURE`, `STATUS_CONFLICT`, `STATUS_DRIFT`, `UNOBSERVABLE`). It only reads. `repair.ts` is the separate step that acts.
- **Bridge to the engine.** `bridge/settlement-bridge.ts` turns saga progress into engine commands (`PromoteRunnerUp`, `RecordSettlement`, `CompleteLot`, `CloseAuction`), reading the engine first so a retry never sends a command twice.
- **Kill switch and stores.** `killswitch.ts` persists the engaged state and wraps a gateway so money-moving calls throw `kill_switch_engaged` before the network; voids and reads pass. `stores/` holds the in-memory stores and JSON-file stores written with fsync, rename and directory fsync.
- **The fake PayPal.** `src/fake/` is an HTTP server and in-process gateway with fault injection, idempotency and webhooks. `src/fake/ASSUMPTIONS.md` lists what the fake assumes about PayPal without having observed it in the sandbox, each row naming the gate that confirms or corrects it.

| `saga/unknown.ts` | an unknown capture stays CAPTURING, never moves to the next bidder |
| `saga/fallback.ts` | after a definite failure, read the truth first, then move to the next candidate at that candidate's own price |
| `saga/remainder.ts` | what to do with the winner's unused authorization, by the G1 `remainderMode` |
| `saga/reauth.ts` | reauthorization is an explicit call only; the saga never calls it |

| `holds/recover.ts` | brings hold records back after a crash |
| `gates/*.ts` | the sandbox gate scripts, run with the `gate:*` scripts in `package.json` |

## Invariants and the tests that guard them

<Accordions type="multiple">
<Accordion title="The saga is deterministic and journal-first">
The same seed gives byte-identical journals; each transition is one compare-and-set save before the next effect. Tests: `test/saga/determinism.test.ts`, `test/saga/machine.test.ts`, `test/saga/property.test.ts`, `test/saga/crash.test.ts`, `test/saga/crashChain.test.ts`, `test/holds/crashWindow.test.ts`.
</Accordion>
<Accordion title="An unknown outcome is never treated as a failure">
Timeouts and 5xx on a POST leave the settlement CAPTURING with an unknown clock (a 429 is not unknown: PayPal refused to run the request, so no clock starts, see the header of `saga/unknown.ts`); the truth is read before acting; after the deadline it goes to review. Tests: `test/saga/unknown.test.ts`, `test/saga/rateLimited.test.ts`, `test/timeout.test.ts`, `test/saga/capture.test.ts`.
</Accordion>
<Accordion title="Only a definite refusal falls back to the next bidder">
Tests: `test/saga/fallback.test.ts`, `test/saga/hrd04.test.ts`, `test/saga/hrd46.test.ts`.
</Accordion>
<Accordion title="A retry repeats the same call">
Request ids do not change on retry or resume. Tests: `test/requestId.test.ts`, `test/transport.test.ts`, `test/fake/idempotency.test.ts`, `test/gates/idempotency.test.ts`.
</Accordion>
<Accordion title="Only the winner pays, the rest is released">
Tests: `test/saga/void.test.ts`, `test/saga/remainder.test.ts`, `test/saga/reviewRelease.test.ts`, `test/saga/capture.test.ts`.
</Accordion>
<Accordion title="A webhook changes nothing unless verified, and the order of delivery does not matter">
Failed verification answers 401 and leaves an audit row; PayPal unreachable answers 503 so it redelivers; a duplicate event id has no effect and still answers 200; an early event is parked for 10 minutes. Tests: `test/webhooks/verify.test.ts`, `test/webhooks/dedupe.test.ts`, `test/webhooks/order.test.ts`, `test/webhooks/redelivery.test.ts`, `test/webhooks/merge.test.ts`, `test/webhooks/budget.test.ts`, `test/webhooks/fast.test.ts`.
</Accordion>
<Accordion title="Only the sandbox is ever called">
Tests: `test/config.test.ts`, `test/guard.test.ts`, `test/security.test.ts`, `test/killswitch.test.ts`, `test/saga/killswitch.test.ts`.
</Accordion>
<Accordion title="Holds respect the ceiling and a double click does not create a second order">
Tests: `test/ceiling.test.ts`, `test/holds/service.test.ts`, `test/holds/hrd07Races.test.ts`, `test/holds/abandonHold.test.ts`, `test/holds/abandonRace.test.ts`.
</Accordion>
<Accordion title="The fake behaves like the sandbox where it has been observed">
`test/conformance/run.test.ts` is the conformance suite that can run against the fake and the sandbox; differences are appended to `src/fake/ASSUMPTIONS.md` when `CONFORMANCE_ASSUMPTIONS` is set. Tests of the fake itself: `test/fake/*.test.ts`.

## Where it sits

`payments` may import `shared` and `engine` (`ALLOWED.payments` in `.dependency-cruiser.cjs`). In `src` it imports `@gavel/shared` types only (`contract/web.ts`, erased at run time) and nothing from the engine: the saga reads the engine's hammer result through the structural type `PlanOutcome`. `server` imports payments and wires it in `boot/compose.ts`; `web` does not import it. See [Settlement saga](/docs/how-it-works/settlement-saga), [Money flow](/docs/how-it-works/money-flow) and [Webhooks](/docs/safety/webhooks).
