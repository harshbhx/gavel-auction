`@gavel/engine` (`packages/engine`) decides what an auction does. It has no clock, no randomness, no network and no disk in its core: a command goes in, <Term id="ledger">ledger</Term> entries come out, and the state of the auction is a fold over those entries. It has no runtime dependencies.

## Responsibilities

- **Decide.** `decide(state, command)` returns either entries to append or a rejection with a reason from `REJECT_REASONS`. Every command type has its own file under `src/decide/` (`place-bid.ts`, `hammer.ts`, `open-lot.ts`, `abort-lot.ts`, `pause.ts`, `promote.ts`, `revoke.ts`, `settlement.ts`, `setup.ts`, `close-auction.ts`).
- **Evolve.** `evolve(state, entry)` folds one entry into the state. `replay` rebuilds the state from a verified chain.
- **Rules.** Pricing for the three modes (`english`, `proxy`, `second_price`), increments, <Term id="soft-close">soft close</Term>, exposure against a bidder's <Term id="ceiling">ceiling</Term>, ranking and the fallback candidate list live in `src/rules/`.
- **Ledger.** Each entry is hashed with the hash of the entry before it (`ledger/chain.ts`). `verifyChain` finds the first bad entry; `exportJsonl` and `verifyJsonl` write and check a file; the `verify-ledger` binary checks an export without a server.
- **Projections.** `projectPublic`, `projectBidder` and `projectAuditor` decide who may see what. Sealed bids stay hidden until the <Term id="hammer">hammer</Term>.
- **Public export.** `publicExport` writes a second, redacted chain (version 4) that anyone can verify; `matchesLedger` lets an auditor holding the private ledger check it.
- **Runtime.** `AuctionRuntime` runs commands of one auction one after another, rebuilds state from the store by verified <Term id="replay">replay</Term> on first use, and tells observers only after the store acknowledged the append.

## Invariants and the tests that guard them

<Accordions type="multiple">
<Accordion title="Same inputs, same ledger (determinism and replay)">
`decide` and `evolve` take time and ids from the command. Replaying a ledger gives the same state digest. Tests: `test/replay.test.ts`, `test/properties/ledger.test.ts`, `test/properties/invariance.test.ts`, `test/golden.test.ts` (fixtures under `fixtures/golden`).
</Accordion>
<Accordion title="A repeated command is answered, not applied twice">
`decide/index.ts` looks the `commandId` up in `state.commands`; the same id with a different type or body is refused. Tests: `test/decide.test.ts` (duplicate of an implicit close), `test/commands.test.ts`, `test/runtime-recovery.test.ts`.
</Accordion>
<Accordion title="The ledger detects any change">
Each entry commits to the one before; `verifyChain` reports `bad_hash`, `bad_prev`, `bad_seq`, `bad_time`, `bad_genesis`, `bad_auction`, `unsupported_version` or `truncated`. Tests: `test/chain.test.ts`, `test/replay.test.ts`, `test/public-export.test.ts` (truncated export), `test/fault/runtime-faults.test.ts`.
</Accordion>
<Accordion title="A bid cannot exceed what the bidder has put on hold">
`over_ceiling` and the exposure sum across lots in the hold scope. Tests: `test/exposure.test.ts`, `test/properties/exposure.test.ts`, `test/validate-bid.test.ts`, `test/place-bid.test.ts`.
</Accordion>
<Accordion title="Soft close extends only accepted bids and never past the hard close">
Rejected bids are not passed to `extension`; a sealed (`second_price`) lot never extends. Tests: `test/softclose.test.ts`, `test/properties/softclose.test.ts`.
</Accordion>
<Accordion title="A runner-up is never charged at its own maximum">
`candidates` prices each candidate as if the earlier ones were out. Tests: `test/candidates.test.ts`, `test/pricing.test.ts`, `test/ranking.test.ts`, `test/properties/pricing.test.ts`, `test/properties/mechanism.test.ts` (toy-model checks of mechanism logic, not bidder behaviour).
</Accordion>
<Accordion title="Private data never leaves in a public export">
Ceilings and private hashes are removed rather than hashed; entries after the first redaction publish no private hash. Tests: `test/public-export.test.ts`, `test/projections.test.ts`, `test/round12-privacy.test.ts`.
</Accordion>
<Accordion title="The core is pure">
No Node I/O outside `src/node` and `src/testing`, and no runtime dependency. Guards: rule `engine-no-node-io` in `.dependency-cruiser.cjs`, `scripts/check-imports.mjs`, `npm run check:bundle`, and the public API test `test/package.test.ts`.
</Accordion>
<Accordion title="One writer per auction, observers see only stored entries">
Commands of an auction run one after another; a result and the observer callbacks come only after the store acknowledged. Tests: `test/runtime.test.ts`, `test/runtime-recovery.test.ts`, `test/runtime-subscribe.test.ts`, `test/runtime-time-bound.test.ts`.
</Accordion>
</Accordions>

<Held title="Reference implementation check">
`test/differential.test.ts` compares this engine with the Python reference on 2000 seeded scenarios, but it only runs when `GAVEL_DIFFERENTIAL_FILE` points at the exported scenario file; without it the test is skipped. The `differential` job in `ci.yml` exports 2000 scenarios with the pinned seed 20261104 and runs it on every pull request; `differential.yml` adds a weekly and manual rotating seed.
</Held>

## Where it sits

`engine` may import `shared` (`ALLOWED.engine = ['shared']` in `.dependency-cruiser.cjs`). In practice it imports nothing from `@gavel/shared` at run time: `src/types.ts` declares its own `Cents` and `EpochMs`, and `test/contract/shared.test.ts` compares the engine's constants (config limits, ceiling presets, reject reasons) with the shared copies. `payments` and `server` import the engine; `web` does not.

The engine records settlement states but does not own the transitions: `SETTLEMENT_EDGES` in `src/events.ts` is the same set as the payments state machine, and `RecordSettlement` refuses any other pair. See [Settlement saga](/docs/how-it-works/settlement-saga) and [Engine and ledger](/docs/how-it-works/engine-and-ledger).
