Webhooks are signature-verified and de-duplicated. They confirm each step of a settlement; the saga also reads the truth at PayPal itself, so a lost webhook does not stall a settlement.

<Charged title="Verified on the sandbox (gate G4)">

Six real deliveries, including a capture and a void, each verified SUCCESS through PayPal's verification endpoint. See [gates](/docs/proof/gates).

</Charged>

## Events the app subscribes to

`PAYMENT.AUTHORIZATION.VOIDED`, `PAYMENT.AUTHORIZATION.DENIED`, `PAYMENT.CAPTURE.PENDING`, `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED` and `PAYMENT.CAPTURE.DECLINED`. Other event types are acknowledged and ignored, so subscribing to them only spends verification calls.

## Behaviour worth knowing

- A duplicate delivery of the same event is dropped.
- A late event for a replaced (reauthorized) authorization is parked and does not void the live hold.
- The certificate URL host is checked against an allowlist (SSRF guard).
- Registering the webhook is a manual step in the PayPal developer dashboard. The webhook id goes into `PAYPAL_WEBHOOK_ID` on the host only and is never committed.

<NotVerified title="Fake only">

Rejecting a tampered event is covered against the fake PayPal only.

</NotVerified>
