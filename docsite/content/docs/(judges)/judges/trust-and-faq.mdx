Short answers for a judge about to try a <Term id="room">room</Term>. Where this page and `docs/GATES.md` disagree, the gate record wins.

<Held title="A bid is a hold, not a charge">

Every PayPal call is against the <Term id="sandbox">sandbox</Term>. A sandbox buyer is a test account with pretend funds. Never sign in with your own PayPal account. Nothing is charged until the <Term id="hammer">hammer</Term>, and then only the winning price is <Term id="capture">captured</Term>.

</Held>

<Accordions type="multiple">
<Accordion title="Is any real money involved?">

No. The hosted server refuses to start judge rooms unless it is on the PayPal sandbox, and refuses fake payments in production mode.

</Accordion>
<Accordion title="Does GAVEL see my PayPal login?">

No. The login happens on PayPal's own sandbox pages. See the [privacy notice](https://github.com/harshbhx/gavel-auction/blob/main/docs/PRIVACY.md).

</Accordion>
<Accordion title="What does GAVEL keep about me?">

The display name you type, your bids and holds (amounts in cents, times and sandbox order ids) and the room <Term id="audit-trail">audit trail</Term>. No analytics, ad identifiers or cookies. Voice is off unless the host turns it on. Records are removed when the demo is shut down.

</Accordion>
<Accordion title="Can I check the auction was not rigged?">

Yes. Every event goes into a <Term id="ledger">ledger</Term> chained by hash; the audit trail link in a room shows it and an edited entry breaks the chain at that entry. See [engine and ledger](/docs/how-it-works/engine-and-ledger).

</Accordion>
<Accordion title="What if the server restarts mid-room?">

The API is set up with a persistent disk, and the settlement saga resumes from its journal. If a room is gone, start a new demo auction. Crash-safe settlement is tested against the <Term id="fake-paypal">fake PayPal</Term> and on the real sandbox (one lot of three holds and one in-process crash); a whole auction on the hosted server is the next step. See [crash recovery](/docs/how-it-works/crash-recovery).

</Accordion>
<Accordion title="What comes next?">

Next steps are a whole auction settled through the hosted server, a real process kill on the deployed host (one on a CI runner is recorded), a guest-card `final_capture` and void, the remainder release read on a buyer balance (inferred today), real-room voice confirmation and the final G3 reading on 12 Nov. See [limits and next steps](/docs/roadmap/limits), [tough questions](/docs/judges/tough-questions) and [real, simulated, recorded](/docs/judges/real-vs-simulated).

</Accordion>
<Accordion title="Something is not working. What now?">

1. Reload and retry the room code.
2. If the room is gone or the host is busy, start a new demo auction.
3. If judge rooms are off or the host is down, open `/demo/scripted` on the web app: a recorded room with no login.
4. If the sandbox login is refused, see [sandbox buyers](/docs/judges/sandbox-buyers).

</Accordion>
</Accordions>
