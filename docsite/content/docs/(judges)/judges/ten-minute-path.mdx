Everything here is PayPal <Term id="sandbox">sandbox</Term> only. You can do most of this in a browser. Only the optional ledger check needs a developer machine with Node 22 and npm. The repository runs its own builds and tests in GitHub Actions.

<Steps>
<Step>

### Minutes 0 to 2: the status and the gates

Follow the [two-minute path](/docs/judges/two-minute-path). It gives you the shape: five real passes (G0 to G4) and one partial result (G5, speech accuracy, measured on test voice clips) with a confirm-step fallback.

</Step>
<Step>

### Minutes 2 to 4: the raw sandbox evidence

Open the committed run logs. They are JSON lines. Tokens, buyer emails and payer ids read `[REDACTED]`.

Gate <Term id="gate-g0">G0</Term> has an evidence file, `docs/evidence/G0/G0-20261109T031839Z.jsonl`, from a re-run on 9 Nov (run 42555610707). It proves connectivity, token scopes and order creation only.

</Step>
<Step>

### Minutes 4 to 6: the settlement logic

Read [Settlement saga](/docs/how-it-works/settlement-saga) and [Retries and unknown outcomes](/docs/how-it-works/retries-and-unknown-outcomes). The <Term id="saga">saga</Term> is a pure state machine in [`packages/payments/src/saga/machine.ts`](https://github.com/harshbhx/gavel-auction/blob/main/packages/payments/src/saga/machine.ts). It was run against the <Term id="fake-paypal">fake PayPal</Term> in full, and against the real sandbox as one lot of three holds and one in-process crash (nightly specs R7, R8 and R10).

</Step>
<Step>

### Minutes 6 to 8: verify the audit trail yourself

The <Term id="engine">engine</Term> writes a <Term id="hash-chain">hash-chained</Term> <Term id="ledger">ledger</Term>. A public export can be checked without a server.

<Tabs items={['Command line', 'In code']}>
<Tab value="Command line">

```bash
npm ci
node packages/engine/bin/verify-ledger.mjs path/to/ledger.jsonl
```

It prints the entry count and head hash, or the first bad entry, and exits non-zero on tampering.

</Tab>
<Tab value="In code">

`verifyPublicExport(entries, { expectedHead })` in `packages/engine/src/ledger/public-export.ts` returns `{ ok: true }` or the first bad index with a reason: `bad_hash`, `bad_prev`, `bad_seq`, `bad_version` or `truncated`. Working calls, including tampered and truncated chains, are in `packages/engine/test/public-export.test.ts`.

</Tab>
</Tabs>

Rejected bids are not in the ledger. The server keeps them in the room log only (decisions D-0014 and D-0029 in `docs/DECISIONS.md`).

</Step>
<Step>

### Minutes 8 to 10: try it live and read the open items

1. Open [/try](https://gavel.dualmindlab.tech/try) and run a sandbox room: start it, join as a bidder, bid, hold the hammer on the console and open the receipt (the [two-minute path](/docs/judges/two-minute-path) has the steps).
2. Prefer no room? Open the [scripted demo](https://gavel.dualmindlab.tech/demo/scripted): it replays recorded events in your browser with no server and no PayPal calls.
3. Want to run it yourself? The [Run it locally](/docs/run) page has the commands. Local runs use `PAYMENTS=fake`, the built-in test PayPal, so no network access or PayPal account is needed. It is a test double and says nothing about the real sandbox; the gates do.

Then read [Tough questions](/docs/judges/tough-questions) and [Security review](/docs/safety/security-review), which lists the open items.

</Step>
</Steps>
