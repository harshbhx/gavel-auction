### Minutes 4 to 6: the settlement logic

Read [Settlement saga](/docs/how-it-works/settlement-saga) and [Retries and unknown outcomes](/docs/how-it-works/retries-and-unknown-outcomes). The saga is a pure state machine in [`packages/payments/src/saga/machine.ts`](https://github.com/harshbhx/gavel-auction/blob/main/packages/payments/src/saga/machine.ts). <Step>

### Minutes 6 to 8: verify the audit trail yourself

The engine writes a hash-chained ledger. A public export can be checked without a server.

<Tabs items={['Command line', 'In code']}>
<Tab value="Command line">

```bash
npm ci
node packages/engine/bin/verify-ledger.mjs path/to/ledger.jsonl
```

It prints the entry count and head hash, or the first bad entry, and exits non-zero on tampering.

</Tab>
<Tab value="In code">

`verifyPublicExport(entries, { expectedHead })` in `packages/engine/src/ledger/public-export.ts` returns `{ ok: true }` or the first bad index with a reason: `bad_hash`, `bad_prev`, `bad_seq`, `bad_version` or `truncated`. Working calls, including tampered and truncated chains, are in `packages/engine/test/public-export.test.ts`.

</Tab>
</Tabs>

Rejected bids are not in the ledger. The server keeps them in the room log only (decisions D-0014 and D-0029 in `docs/DECISIONS.md`).

</Step>
<Step>

### Minutes 8 to 10: run the fake-PayPal demo and read the open items

1. Follow the "Run it" section of `README.md`. The default run is `npm ci`, then `npm start -w @gavel/server` with `PAYMENTS=fake` and `PAYPAL_ENV=sandbox` (the README lists the other variables, with development values).
2. `PAYMENTS=fake` uses the built-in fake PayPal: no network access and no PayPal account are needed. Production mode refuses fake payments.
3. The scripted `/api/demo/*` routes are mounted only with `DEMO_MODE=1` and `PAYMENTS=fake`.

The fake PayPal is a test double. What you see there says nothing about the real sandbox; the gates do.

Then read [Tough questions](/docs/judges/tough-questions) and [Security review](/docs/safety/security-review), which lists the open items.

</Step>
</Steps>
