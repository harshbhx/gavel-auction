## The scripted tour

Copy `packages/web/.env.example` to `packages/web/.env.local` (the web app needs those `VITE_*` values), run the web app in development (`npm run dev -w @gavel/web`) and open `/r/demo/screen?scripted=1`. The flag plays a recorded scenario in the browser with no server and no PayPal calls, and the provenance tag says Scripted. Add `at=<ms>` to hold the scenario at one moment, for example `/r/demo/bid?scripted=1&at=3000`. Only development builds honour the flag: the hosted production build ignores it. On the hosted site the tour link on `/try` opens `/demo/scripted`, which plays the recorded room in the tab in every build.

## Join as a bidder

1. Open the QR link from the launcher, or `/join/<roomId>` and type the six-character code.
2. Choose "Join as bidder" and pick a <Term id="ceiling">ceiling</Term>. The page creates a PayPal order with intent AUTHORIZE for that amount.
3. Approve it. A sandbox buyer signs in with a sandbox personal account; in a fake-payments room the page approves after a short pause with no sign-in.
4. The ladder shows your <Term id="hold">hold</Term> as HELD. A hold is a promise, not a charge.

The ceiling is set on a slider and approved with a press-and-hold button (3 seconds, or Space or Enter on a keyboard, with a two-tap alternative). The help button explains the hold: hatched is held, solid is charged, hollow is released.

## Bid

- QR: after joining, the bid screen has a quick-bid button, increment buttons and a custom amount. Bids above your ceiling are blocked.
- Typed entry: the auctioneer console has "Manual entry" to place a bid for a registered bidder.
- Voice: the `/audio` socket turns a spoken bid into a structured bid and asks for confirmation. The console has an auctioneer microphone that is enabled only when the server reports a live speech provider; otherwise it is disabled and says why. Every spoken bid still asks for a confirm.

## Expected result at the hammer

1. The winner's hold is <Term id="capture">captured</Term> for the **winning price only**. A $500 ceiling and a $350 winning bid captures $350.
2. Every other hold is <Term id="void">voided</Term>. The winner's unused remainder is closed by PayPal (inferred, not observed).
3. The ladder shows HELD, then CAPTURED for the winner and VOIDED for the others, with the source of each confirmation (webhook or lookup).
4. Exactly one capture happens even if the server stops mid-settlement and resumes. If PayPal's answer is unknown, the settlement stops for review.

<NotVerified title="Timing">

A hold older than 2 hours (`GAVEL_HOLD_MAX_AGE_MS`, 7,200,000 ms) when settlement starts is flagged stale, and a stale hold is still captured. PayPal's honor period is unproven (gate G3), so register, bid and hammer within one sitting.

</NotVerified>
